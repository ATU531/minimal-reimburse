# 票易理 UI/UE 重塑设计规格

日期：2026-05-24

## 背景

当前小程序已经具备 v1 发票收集、票夹管理、手动录入、发票详情和原票 PDF 导出能力，但页面视觉比 `票易理UI设计.html` 更基础。用户目标是按照该设计稿优化界面 UI 和 UE。

本轮设计确认采用以下顺序：

1. 以 `票易理UI设计.html` 为视觉基准，内容区优先做 1:1 复刻。
2. 保留微信原生顶部导航栏和原生 TabBar，不做自定义顶部品牌栏、手机外框、微信胶囊或自绘底部 Tab。
3. 在视觉复刻后，裁剪 v1 不需要或未上线的内容，并替换为当前真实功能文案。

## 范围

覆盖 v1 可见页面和相关入口：

- 首页：`miniprogram/pages/index`
- 票夹：`miniprogram/pages/folder`
- 我的：`miniprogram/pages/profile`
- 手动录入/编辑：`miniprogram/pages/manual-entry`
- 发票详情：`miniprogram/pages/invoice-detail`
- 导出中心：`miniprogram/pages/export-center`
- 全局样式和原生 Tab 图标资源：`miniprogram/app.wxss`、`miniprogram/app.json`、`miniprogram/images/icons`

不覆盖：

- 报销流程、报销单、审批、团队协作等 v1 未展示能力。
- 微信卡包同步、扫码解析、Excel 导出、打印、企业管理等暂不开放入口。
- 自定义顶部导航栏和自定义底部 TabBar。

## 设计原则

- 视觉还原优先：页面内容区的卡片结构、图标、字体层级、间距、圆角、阴影和主色按设计稿落地。
- 原生壳层保留：微信原生顶部导航栏和原生 TabBar 继续承载系统导航，只调整颜色、标题和图标资源。
- 功能真实：不展示 `PRO 会员`、`电子签名 L3`、强税务背书等当前 v1 不具备或不可验证的承诺。
- 文案收敛：设计稿中的营销表达改写为 v1 已实现能力，如 OCR 识别、原票归档、重复发票校验、PDF 合并导出。
- 操作连续：保留现有路由、云函数调用、票夹筛选、选中导出、手动保存、详情编辑和删除逻辑。

## 视觉系统

### 色彩

主色按设计稿使用靛蓝与紫色：

- 深色 Hero：`#1E1B4B`、`#4338CA`、`#4F46E5`
- 紫色点缀：`#8B5CF6`
- 页面背景：`#F4F7FB` 或接近的浅灰蓝
- 卡片背景：`#FFFFFF`
- 主文字：`#1F2937` / `#101828`
- 次级文字：`#8DA0BB` / `#94A3B8`
- 警示或 PDF 点缀：玫红/红色系，仅用于原票 PDF、删除等明确语义

### 字体

小程序样式使用以下字体栈：

```css
font-family: Inter, "Noto Sans SC", "PingFang SC", system-ui, sans-serif;
```

如果运行环境无法加载 Inter 或 Noto Sans SC，回退到 PingFang SC 和系统字体。实现不依赖远程字体文件。

### 图标

设计稿中的图标需要在小程序中用本地资源或内联可维护结构落地：

- 首页录入：相机、聊天、相册、编辑
- 核心服务：票夹、PDF 文件
- 票夹：搜索、选择态、右箭头或状态图标
- 我的：发票抬头、说明、PDF、客服、问题、联系
- 操作区：关闭、下载、删除、编辑等

图标颜色和底色需匹配设计稿的语义色块，而不是继续使用单字占位。

### 卡片与间距

- 首页 Hero 大卡使用设计稿同款深色渐变、24-32rpx 级圆角、内部半透明统计面板。
- 内容标题使用左侧紫色竖条加粗标题，右侧可放轻量说明。
- 普通卡片使用白底、浅边框、轻阴影，圆角接近设计稿。
- 表单输入和筛选按钮使用浅灰底、圆角、清晰选中态。
- 底部固定操作栏使用半透明白底或白底加阴影，并预留安全区。

## 页面设计

### 首页

内容区从设计稿 Hero 卡开始，不复刻设计稿上方手机外框、品牌栏或胶囊。

结构：

- 深靛蓝渐变 Hero 卡
  - 胶囊标签保留布局，文案使用“智能识别”
  - 主标题保留“让发票整理更从容”
  - 副文案改为“OCR 录入 · 原票归档 · PDF 合并导出”
  - 统计面板展示“本月未整理发票”和“本月录入金额”
- “便捷发票录入”区块
  - 左侧紫色竖条
  - 右侧说明“支持批量上传”
  - 2x2 录入卡：智能识别、聊天文件、手机相册、手动录入
  - 每张卡使用设计稿同款图标、标题和说明
  - 智能识别保留“推荐”角标
- “核心服务”区块
  - 票夹归集：跳转票夹，说明改为“发票统一归集，快速检索筛选”
  - 原票 PDF：跳转票夹或导出相关流程，说明改为“原票附件合并导出，便于归档”
- 提示卡
  - 保留设计稿提示卡视觉
  - 文案避免强监管承诺，表达为“电子发票报销时建议同步保留原票附件，票易理可帮助整理并导出原票 PDF 包”

交互：

- 录入卡沿用当前 `handleEntryTap` 和页面跳转。
- 核心服务沿用当前 `handleFeatureTap`；“原票 PDF”入口跳转到票夹并默认切换为可导出筛选。

### 票夹

结构：

- 顶部搜索筛选卡
  - 搜索输入带搜索图标
  - 保留“筛选”入口
  - 分段按钮：全部、本月、可导出
- 统计卡
  - 待整理
  - 本月金额
  - 已选待导
- 发票列表
  - 设计稿式白色卡片
  - 顶部展示选择态、发票类型、来源、金额
  - 中部展示发票标题、日期、抬头
  - 底部展示状态标签和详情入口
  - 选中态使用靛蓝边框与轻阴影
- 底部固定导出栏
  - 展示已选数量
  - 主操作为“导出 PDF”
  - 无选中时按钮展示禁用态；点击禁用态不触发导出，并保留“请先勾选要导出的发票”提示

交互：

- 保留现有搜索、筛选、选中、打开详情、导出 PDF 逻辑。
- 本月筛选从固定 `2026-03` 改为按运行时当前年月计算。
- 本地草稿不可导出的提示逻辑保留。

### 我的

结构：

- 深色用户信息卡
  - 复刻设计稿深色卡、头像区、账号说明和三列统计
  - 删除 `PRO 会员`
  - 用户名展示“票易理”
  - 账号说明改为“发票收集与原票 PDF 归档”
- 三列统计
  - 常用抬头
  - 导出模板
  - 常用科目
  - 数值沿用当前静态数据或现有数据源
- 分组菜单
  - 发票资料：发票抬头、收票说明与指引
  - 导出设置：PDF 导出模板
  - 服务支持：在线客服、常见问题、联系我们
  - 每个菜单项加对应图标和右箭头

交互：

- 保留当前 `handleTap` 跳转和 toast。
- 无真实页面的支持项继续提示，不新增未实现页面。

### 手动录入/编辑

约束：

- 不做设计稿网页式弹层。
- 保留独立小程序页面和当前保存/更新逻辑。

结构：

- 顶部说明卡或紧凑标题区贴近设计稿弹层标题视觉。
- 表单按设计稿改为浅灰输入框、圆角边框、紧凑标签。
- 核心字段优先：发票类型、销售方、开票日期、金额、发票抬头、备注。
- 当前已有补充字段保留，但视觉上弱化为次级分组。
- 底部固定主按钮沿用“保存到票夹”或“更新发票”。

交互：

- 表单校验、重复检测、本地草稿/云端保存逻辑不变。
- 错误态使用红色文字和边框，不改变错误条件。

### 发票详情

结构：

- 金额 Hero 卡
  - 保留金额、标题、状态标签
  - 视觉统一到深浅渐变和设计稿圆角
- 发票信息卡
  - 发票类型、代码、号码、日期、购买方、销售方、来源
  - 使用设计稿式行分隔、右侧值布局
- 流转记录
  - 使用时间线点和轻量说明
- 发票操作
  - 编辑发票
  - 删除发票
  - 删除保持危险色
- 底部 PDF 导出按钮
  - 仅当当前逻辑允许时展示

交互：

- 编辑跳转、删除确认、导出 PDF 逻辑不变。

### 导出中心

结构：

- 顶部说明卡改为设计稿 PDF 导出清单风格。
- 导出格式只展示 PDF，不展示 Excel、打印或其他未开放格式。
- 导出记录使用设计稿任务卡视觉。
- 导出预设使用白底列表或 pill。
- 底部固定操作栏保留“刷新记录”和“生成 PDF”。

文案裁剪：

- 不展示“电子签名 L3”“数字证书安全等级”等未上线能力。
- 状态文案使用“正在合并原票附件”“生成可转发 PDF 文件”“导出记录将展示在导出中心”。

交互：

- 当前刷新、创建、下载、打开或转发 PDF 的逻辑不变。
- 导出失败时保留现有错误弹窗，并优化中文提示可读性。

## 数据流

本轮主要是 UI/UE 调整，数据流保持现状：

- 首页使用当前静态入口和汇总数据；若需要使用票夹真实统计，只能在不影响稳定性的前提下复用已有发票列表数据。
- 票夹通过 `listInvoices` 获取云端发票，并合并本地草稿。
- 手动录入通过 `createInvoice`、`updateInvoice`、`findDuplicateInvoice` 等现有云函数能力保存。
- 发票详情通过 `getInvoiceDetail` 获取并通过现有接口编辑、删除。
- 导出中心和票夹导出继续调用 `generateExportPdf`。

不新增云函数、不调整数据库结构。

## 错误处理

- OCR、保存、列表拉取、PDF 导出等错误处理沿用现有逻辑。
- UI 改造不得隐藏失败提示、loading 状态或不可导出原因。
- `EXPORT_UNSUPPORTED_ATTACHMENT` 继续展示缺少原始图片或 PDF 的发票名称。
- 本地草稿无法导出时继续提示“请等待同步”或等价说明。
- 表单字段错误继续就近展示在字段下方。

- 首页内容区与 `票易理UI设计.html` 的 Hero、录入卡、核心服务、提示卡保持高还原度。
- 原生顶部导航栏和原生 TabBar 保持可用，不出现双导航或双 Tab。

- 票夹选择、筛选、搜索、详情跳转和 PDF 导出可正常操作。

## 实施边界

实现应优先修改 WXML/WXSS 和必要的数据字段，避免重写业务逻辑。若为了图标需要新增本地 SVG 或图片资源，应放在 `miniprogram/images/icons` 下，并在文档或命名中保持语义清晰。

若发现现有页面结构难以 1:1 承载设计稿内容区，可做局部 WXML 重排，但不得改变页面路由和云函数协议。
